Create GitHub token ↗

Opens GitHub with a 90-day expiry and read-only permissions for Metadata, Dependabot alerts, Code scanning alerts, and Secret scanning alerts.

  1. Check Resource owner: GitHub defaults to your signed-in personal account.
  2. Under Repository access, choose Only select repositories and select the repositories you want to monitor.
  3. Review the permissions, then click Generate token on GitHub.
  4. Copy the token into Access token above, then click Validate & save connection.

GitHub token documentation ↗

Create GitLab token ↗

Enter an HTTPS instance URL without credentials, query parameters, or a fragment in Provider URL to enable the token link.

Opens the personal access token page on your configured GitLab instance, including any installation subpath, with only read_api requested.

  1. Sign in to your corporate GitLab account. Choose Legacy token if the page offers token types.
  2. Use My Code Dashboard as the token name and choose an expiration allowed by your corporate policy, for example 90 days.
  3. Confirm that read_api is the only selected scope, then create the token on GitLab.
  4. Copy the token into Access token above, then click Validate & save connection.

If your GitLab version uses a different page, open your avatar → Edit profile → Access → Personal access tokens and select only read_api.

GitLab token documentation ↗

Minimum permissions

GitHub: metadata and read access for Dependabot alerts, Code scanning alerts, and Secret scanning alerts. Use a separate fine-grained token per resource owner. Organization approval and security feature eligibility may also be required.

GitLab: read_api and a role permitted to read project vulnerability reports. Ultimate licensing does not configure scanners automatically.
