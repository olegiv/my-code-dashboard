# Tests and code review

The workflow adapts [ocms-go's test gate](https://github.com/olegiv/ocms-go/blob/09c2bd1f2b010f48fad2e45ca5c7089baef7b9c1/scripts/test-gate.sh), [pre-push hook](https://github.com/olegiv/ocms-go/blob/09c2bd1f2b010f48fad2e45ca5c7089baef7b9c1/.githooks/pre-push), and lint rules. Local checks require Go, Git, Bash and Make. No Node.js or Docker is required. Pinned Go tools download automatically; missing tools and failed checks stop the gate.

## Local checks

| Command | Checks |
| --- | --- |
| `make build` | Compile with Go 1.26.9 |
| `make test` | All packages with the race detector and `-count=1`, bypassing cached test results |
| `make lint` | gofmt and golangci-lint v2.15.0: staticcheck, errcheck, errorlint, govet, revive, gocritic, duplication and complexity checks |
| `make check` | Tests, lint, vet, tidy diff, module checksums, govulncheck v1.9.0 and browser checksums |
| `make commit-check` | Export the exact index to a temporary directory and run `make build check`; reject an empty index or an index changed during checks |
| `make pr-check` | Check the exact public index against the release manifest, then ShellCheck, actionlint v1.7.12 and Gitleaks v8.30.1 in a temporary export; requires ShellCheck on PATH |
| `make package-check` | Build four target archives and corresponding source, then verify checksums, source/documentation bytes, binary metadata, component notices and the native version |
| `make install-test-gate` | Install the repository pre-push hook, preserving existing hooks and global Git configuration |

`make check` checks the working tree. Before the first application commit, stage the intended public files and run **`make commit-check`** and **`make pr-check`**. Both work before HEAD exists; unstaged changes and ignored private data are excluded. Checks create no commit and make no push. ShellCheck is an additional development tool (`brew install shellcheck`, MacPorts `port install shellcheck`, or Debian/Ubuntu `apt install shellcheck`); a missing checker fails the gate. Packaging is separate: run `make package-check` and inspect target-specific upstream notice contents before a release. This command checks the working tree against the manifest, so run it on an export of the same candidate reviewed by the staged gates. The temporary export is source selection, not a security sandbox for untrusted PR code.

Tests use synthetic providers, loopback servers and temporary databases. Gate tests use disposable Git repositories; fixture commits exist only there, to test clean pushes, wrong refs, staged/working-tree differences that cancel against HEAD, dirty files, failed checks and deletion-only pushes. Tests also cover the unborn index, exclusion of local files, index changes during checks, idempotent hook installation and existing hook/configuration preservation. They do not access real provider credentials or runtime installations.

HTTP Host regressions exercise implicit and explicit port 80 for IPv4, bracketed IPv6 and localhost, plus nondefault-port controls and rejected foreign/malformed authorities. They check settings, assets and health responses, security headers, missing/incorrect CSRF tokens, cross-origin rejection and persistence after an accepted settings POST. These use the in-process HTTP harness with synthetic listener addresses; they do not bind privileged port 80 or change a real installation.

Stale-category attention regressions use a fixed clock and synthetic coverage to check fresh collections, exactly 48 hours, just over 48 hours, mixed fresh/stale categories, multiple stale categories, and stale categories already marked failed, disabled, enabled or warning. Missing-success and paused-repository controls verify the separate stale counter and portfolio selection rules. View and rendered-page assertions cover Overview, the repository list and details, including retained active findings and unchanged stored coverage after reads. Run this focused harness with `GOTOOLCHAIN=go1.26.9 GOWORK=off go test -race -count=1 ./internal/web -run '^TestStaleCategoryAttention$'`.

The same harness covers stale analysis with fresh collection, fresh analysis with stale collection, both timestamps stale, multiple stale analyses, exact/just-over-48-hour analysis boundaries, future/unreported analysis, and overlap with failed, disabled, enabled or warning states. Paused repositories retain their own attention warning without affecting portfolio totals. Analysis-only staleness raises attention without incrementing the stale-collection counter, and the tests check both view data and the three rendered summary pages.

Restore regression tests use synthetic archives and an observed in-memory credential backend. They cover shadow identities, SQLite BLOB/NULL keys, JSON representations, unsupported schema objects and triggers that clear quarantine immediately or on refresh. All five application record tables are checked for malformed data and mismatches between decoded identities/indexed fields and native SQLite columns before destination replacement, including history beyond UI limits. Rejected archives leave the destination byte-for-byte unchanged. Matching duplicate, case-aliased and escaped selection fields remain safely deselectable/reselectable after restore, preserve metadata, stay excluded from the next refresh and produce a valid subsequent backup. The provider factory stops before any network request. Genuine backups preserve selections, findings and history, and remain blocked from credential lookup after restart; the engine suite also verifies explicit reconnection. Run the focused boundary checks with `GOTOOLCHAIN=go1.26.9 go test -race -count=1 ./internal/store ./internal/platform ./internal/engine` before the full staged gate.

Finding JSON fixtures add unknown raw-response, source-snippet and secret properties, including an escaped key and a sensitive-looking field name. Actual restore must reject them without echoing imported data, changing destination bytes/identity, creating recovery copies or leaving extraction files. Null, malformed and trailing JSON remain rejected. Valid controls populate supported finding metadata and exercise known case aliases, escaped keys and whitespace; they preserve selection, native/active fields and credential quarantine through export and a second restore. These are structural allowlist tests, not a content-classification guarantee for supported text fields.

Web regressions render normal and crafted imported connection IDs, check that discovery/removal actions remain fixed, and exercise escaped hidden IDs, POST-body precedence, credential quarantine and CSRF. Reconnection tests reject provider/URL mismatches before the fake provider is called, retain quarantine on rejection, and accept explicit matching recipients. Browser verification also checks recipient selection, guidance and token clearing, the effective HTMX 4 configuration (`includeIndicatorCSS: false`), strict CSP, Alpine selection and HTMX filter/refresh responses. Engine tests persist rate-limit deadlines from manual refresh across restart, daily-slot and schedule preference changes without consuming scheduled attempts, then verify collection resumes after the deadline. GitLab fixtures separately verify that optional scanner-query rate limits preserve complete findings and propagate backoff while unavailable metadata leaves coverage unknown.

Repository-view tests keep retained active findings visible after deselection through both the detail page and its explicit findings filter, while portfolio totals and default findings remain limited to monitored repositories. History fixtures mix UTC and offset-bearing timestamps at exact seconds and nanosecond boundaries, checking both newest-first ordering and exact retention cutoffs for runs and changes.

Retention regressions shorten preferences or tick a disabled schedule, including an active-refresh control, without calling a provider. Expired changes/runs disappear while cutoff/newer records remain in the database and its next backup. Change-history fixtures place more than 200 newer events on a paused repository: monitored events still fill the newest-first 200-event cap, selection swaps change the feed and empty selection returns no events. HTTP fixtures verify Activity and Overview render retained monitored history and repository details still render current findings.

Repository restore fixtures keep JSON and indexed identities consistent while testing empty, nonnumeric, nonpositive, overflowing and noncanonical decimal IDs, blank names and provider/connection mismatches. Actual Restore rejects these before replacement, preserving destination bytes, installation identity and recovery-directory state. Valid GitLab/max-int64 controls and existing GitHub controls retain selection, findings, rediscovery and credential quarantine. These archives and destinations are temporary synthetic fixtures.

HTMX history-restoration requests receive the complete page shell with navigation and filters. Filtering and pagination within Findings still receive only the findings fragment. Pagination from Overview or repository details uses a full navigation to Findings. The pagination regression follows the rendered link, checks the response shell and preserves the active/repository scope; the Findings control retains HTMX behavior. Synthetic browser Next/Previous and Back/Forward flows exercise these separate consumers.

Secondary-limit fixtures return 403, a nonzero primary remaining count, and both forms of `Retry-After`; they verify classification, deadlines and suppression of later requests. Existing engine deadline tests cover persistence across restart and daily slots. Custom schedule fixtures cover Zurich and New York skipped/repeated times; an engine regression proves yesterday's consumed slot is not replayed before the shifted spring slot and that the new slot runs once.

Channel-controlled discovery tests overlap both successful and failed responses with credential replacement/removal. They verify the current identity/name/status survives and stale repositories are not saved. Unchanged connections still accept successful discovery and display ordinary errors. These fixtures use memory credentials and fake providers only.

Credential-removal regressions inject a SQLite UPDATE failure with a temporary trigger: the original connection, credential and epoch must survive. A provisioned temporary credential file supplies a deletion failure; disconnection must persist across a new engine instance, repeated discovery, refresh and repeated removal attempts without provider calls. Memory-backed normal, idempotent, restored-credential and explicit-reconnect controls retain active findings. These are synthetic storage/backend failures, not physical disk-full tests or real Keychain operations.

Channel-controlled refresh tests replace/remove credentials during repository metadata and finding collection. They check that outstanding metadata/results are discarded, previous complete findings and coverage survive, activity records the affected categories, and later repositories do not reuse that adapter. An independent connection still imports, unchanged credentials complete normally, and a subsequent refresh succeeds with the replacement credential.

Repository metadata fixtures exercise successful HTTP responses containing null, empty objects, missing/nonpositive IDs, missing paths and mismatched immutable IDs for both providers. Rejection retains prior metadata; valid renames, branch and archive changes still import. Store and engine regressions independently reject changed external IDs, preserve active findings and historical repository names on failure, and validate backups produced after rejected updates and normal renames.

Discovery identity regressions cover hostname case and implicit/explicit HTTPS port 443, single legacy IDs, distinct nondefault ports and installation subpaths. Alias rediscovery preserves selection, credential ownership, findings, coverage and change history, updates names/archive state and produces a valid backup. Existing ambiguous legacy duplicates reject the entire discovery without changing stored repositories. These fixtures use temporary databases and synthetic connection URLs.

Coverage regressions keep enabled scanners without latest-pipeline run evidence visible in portfolio/repository summaries and activity while retaining imported active findings. Pagination tests exercise literal URI commas/semicolons, quoted attributes and relations, multiple Link fields and complete two-page imports. Restore fixtures reject finding and repository links outside the connection's HTTPS origin before changing the destination; empty links, canonical GitHub links and configured GitLab origins remain valid.

GitHub analysis-endpoint fixtures first return active alerts, then exercise recognized disabled/missing-analysis errors, genuine denied/expired access, ambiguous or untrusted errors, rate-limit precedence and normal success. They check classification, requested ref, discarded partial alerts, native active status and the absence of fabricated timestamps or raw error details. Existing engine and store consumer tests separately verify retained complete findings/analysis, saved activity reasons and retries only for genuine failures; the adapter and consumer contracts are tested separately rather than through live GitHub.

Partial-import UI fixtures persist zero, one or all categories, plus unsupported/denied categories and a paused selection. They verify all seven categories appear exactly once, missing entries remain unknown without timestamps, stored evidence is unchanged and placeholders are never written to the database. Overview, repository list/detail and explicit Findings responses preserve active findings and honest coverage counts. Complete imports keep their collected status; paused repositories stay outside portfolio totals. These use the HTTP/render harness, without killing a real application process or connecting an account.

GitLab multi-scanner fixtures cover DAST/API fuzzing, SAST/Advanced SAST, container/cluster scanning and IaC/SAST IaC. For each category they check partial, complete, absent, single, unrelated and case-normalized runs. A partial run names the missing scanner, keeps the category enabled and preserves complete active findings without fabricating analysis times. A disposable web fixture feeds those snapshot contracts through actual refresh, storage, overview/detail summaries, Activity and Findings responses, covering both missing and complete run evidence.

Refresh resume tests interrupt a synthetic three-repository portfolio with an inherited one-second deadline, exercising the same cancellation path as the 30-minute budget. They reopen the real temporary database and check manual and scheduled retries visit the pending tail first, retain prior active findings, clear progress on completion and then return to ordinary order. Controls cover changed selection, missing/deselected checkpoints, empty selection and independent installations. No real provider or 30-minute wait is involved.

The interrupted installations also produce backups that pass the restore validator with saved progress. A disposable checkpoint-write failure fixture stops collection after the completed repository, retains its imports and earlier findings, and records a partial run; its normal control completes both repositories. This uses a narrow storage fault seam without changing the real database or provider implementation.

Restore connection regressions reject invalid HTTPS targets, unsupported/missing providers and noncanonical GitHub targets even when all links are empty or the connection has no repositories. Rejection preserves destination bytes/identity and creates no recovery directory. Valid GitHub and GitLab targets, including permitted paths/ports, retain empty links, selection, active findings and credential quarantine, then pass subsequent store discovery. GitLab GraphQL fixtures map `SAST_ADVANCED`/`SAST_IAC` and the existing SAST/IaC spellings through complete imports, all four scanner states and activity attention, with no fabricated analysis timestamps.

Reconnect recipient tests accept restored GitHub/GitLab URLs with surrounding whitespace or a trailing slash using the same validation as the submitted URL. Browser fixtures verify the displayed recipient, provider call, memory credential save and quarantine clearing while rejecting different providers/hosts/ports/installation paths and invalid targets. Headless fixtures exercise the actual command with missing temporary credential files: matching targets must reach credential lookup, retain quarantine on that failure and preserve creation time; target changes must fail before lookup. No headless provider authentication or real credentials are used.

GitHub analysis fixtures keep each stream's last success after a failed upload, preserve the oldest successful timestamp/ref/commit across streams, retain warnings and leave timestamps unknown when no success exists. Linux startup tests substitute a temporary `xdg-open` script: HTTP requests and cancellation must complete while that opener stays running, and an immediately exiting opener must also work. These tests never launch a real browser; the Linux-specific test is skipped on macOS.

Slash-collision cases keep tool/category/ref tuples independent and retain warnings and the oldest successful evidence. Origin fixtures exercise implicit/explicit HTTPS port 443 in both directions, host case, IPv6 and matching nondefault ports. Foreign hosts, credentials, HTTP downgrades and different effective ports are rejected before a request is sent. An in-memory GitLab discovery flow follows a canonical redirect and next-page link without dropping authentication or repository URLs. The restore matrix checks the same default-port variants for both findings and repositories while preserving the destination on rejection.

Service installation's delayed-close error is verified with a disposable Go overlay of the existing platform harness: its file wrapper returns a synthetic Close error, its plist path is temporary, and launch commands are replaced with stubs. The failure retains the installed executable, removes the temporary copy and stops before plist/agent changes; a normal control copies executable bytes/mode and renders the plist. This fault-injection fixture is local review evidence outside tracked source, rather than a physical disk-failure test or a real LaunchAgent installation.

Listener-port regressions reject overflow, out-of-range, negative, signed, named, malformed and non-loopback addresses. Both real CLI startup and service-install entry points must return before creating a temporary installation directory. Valid IPv4/IPv6 loopback controls cover ports 0, 1, 80, 7364 and 65535 and decimal leading zeros; the existing demo test actually serves and shuts down on an ephemeral port. Successful LaunchAgent installation is not invoked by these port tests.

Restore extraction checks copy errors, close errors and copy-error precedence with a synthetic writer. A disposable overlay also injects a close-only error into the actual Restore path: validation and replacement must not run, destination bytes/identity stay unchanged and extraction files are cleaned up; a normal control restores and quarantines connections. Plist tests force a real partial write using a file-size resource limit confined to a child test process and an ordinary temporary path. New/replacement success controls check content and private mode; the failure must preserve the previous file and remove its temporary copy. A separate InstallService overlay stubs all service paths/commands and verifies a plist close error stops before any launch operation, while successful publication proceeds. These checks do not simulate power loss or invoke a real LaunchAgent.

Recovery fixtures restore the same valid archive into new, healthy, corrupt and newer-schema destinations, invalid settings/identities, a newer-schema database with settings in its WAL, and orphaned sidecars. They check private recovery directories, preservation of existing database/WAL/journal bytes, retention of a readable local identity or generation of a fresh identity, and credential quarantine through the refresh consumer. SHM is checked for preservation but not byte equality because SQLite may update that transient index during a read. The CLI is also exercised with temporary installations. Focused fault-injection evidence covers move/install failures and rollback; those disposable fixtures stay outside tracked source.

Release tests use a fixture-local Go stub and disposable source tree to prove that unlisted documents and Go files do not reach builds or archives, while listed documentation remains included. Invalid, duplicate, missing, traversal and symlink manifest entries stop preparation. Separately run the real release script, inspect all four binaries and the source archive, verify checksums and target-specific notices, and compare packaged source with the reviewed [file manifest](../scripts/release-files.txt). Keep that manifest current when adding public source files.

PR gate fixtures exercise all three checkers, failure propagation, manifest drift, index changes and exclusion of unstaged/private files without creating a project commit. Archive-verifier fixtures accept matching source and reject changed/unlisted files, missing source/notices, path traversal, links, AppleDouble metadata and malformed binary metadata. Real packaging additionally verifies all cross-target build metadata and the current host's version command; foreign-target binaries are not executed locally.

The pre-push hook requires each non-deletion ref to point to HEAD and rejects staged, unstaged and untracked changes, then runs the staged gate. Deleted refs do not run tests. A global `core.hooksPath` must chain to `.git/hooks/pre-push`; the installer reports this requirement and preserves the configuration. Hooks are local guards; CI is still required.

## Codex and Codex Security

Before approving the first application commit, run both against the candidate that passed the checks:

1. An independent, ephemeral, read-only Codex code review for bugs and regressions. Without an initial HEAD, review an exported staged directory. Do not create an artificial project commit to supply a review base.
2. A **Codex Security Standard scan** covering credentials, untrusted provider responses, private storage, local HTTP protections and distribution. `govulncheck` checks known Go vulnerabilities; it does not replace this source review.
3. Validate findings, fix confirmed blockers, rerun affected checks and refresh review evidence after relevant changes. Keep reports and the tree ID in ignored output or the security workbench. Missing, blocked and incomplete reviews remain pending, even if a wrapper exits successfully.

AI reviews are development checks; the app and ordinary Go tests require no AI service. Record actual review results and coverage limitations in the commit preview. Record direct normal/failure behavior and affected consumers separately from baseline checks; see [validation](validation.md).

Hosted review setup, actual completion checks and access prerequisites are described in [GitHub validation](github-validation.md). They apply to the first application PR as well as later PRs. Never store AI API keys in this public repository or its workflows.

## GitHub checks

**Go checks** runs `make build check` on macOS and Linux. **PR quality** checks workflows, shell scripts, secrets and release archives. **CodeQL** separately analyzes Go, browser JavaScript and Actions. Dependency review compares PRs targeting `main` with their base. Actions use full commit SHA pins; pinned Go tools use the module checksum infrastructure. GitHub manages Actions' internal JavaScript runtime; the project has no npm dependencies or frontend build requirement. See [the complete check matrix and two-commit publication sequence](github-validation.md). A README/LICENSE-only bootstrap has no application checks; all code is introduced by the subsequent PR.

Verify actual hosted results after the authorized push/PR. Local success cannot establish hosted status, Linux runtime behavior or compatibility with every provider version. Commit, push, repository settings and publication each require the user's authorization.
